# BIM Handoff Contract Specification

## Overview

The **BIM Handoff Contract** establishes a predictable, versioned JSON data contract that accompanies every 2D architectural DXF floor plan generated by **Sketch-to-CAD**. It bridges the gap between 2D vector drafting and downstream 3D Building Information Modeling (**`dxf-to-3d-bim`**).

Rather than forcing the downstream BIM skill to rely solely on heuristic visual recognition or brittle layer parsing of the raw DXF, the companion handoff file provides authoritative, structured semantic metadata directly derived from the approved floor-plan model.

---

## File Naming Convention

Every generated drawing produces a matched pair of deliverables:
- **Vector CAD Drawing**: `<drawing-name>.dxf`
- **Companion BIM Metadata**: `<drawing-name>.handoff.json`
- **Visual Preview (Optional)**: `<drawing-name>.png`

Example:
```
tests/output/
├── furnished-plan.dxf             # Editable 2D CAD floor plan
├── furnished-plan.handoff.json    # Companion structured BIM handoff
└── furnished-plan.png             # Visual raster preview
```

---

## Schema & Versioning

- **Schema File**: `skills/sketch-to-cad/schemas/bim-handoff.schema.json`
- **Schema Dialect**: JSON Schema Draft-07 (`http://json-schema.org/draft-07/schema#`)
- **Current Version**: `1.0.0`

Every handoff document must include `"schemaVersion": "1.0.0"` at the root level.

---

## Coordinate System and Units

To eliminate ambiguity across CAD and BIM tools:
- **Length Units**: Millimeters (`"mm"`). All coordinates, thicknesses, widths, and offsets are stored as millimeter floats.
- **Coordinate System**: `Cartesian2D_RightHanded_YUp`.
  - Origin `(0.0, 0.0)` is at the lower-left corner of the exterior building envelope.
  - Positive X extends to the right (East).
  - Positive Y extends upwards (North).
  - Rotations are measured in degrees counter-clockwise from the positive X axis ($0^\circ = \text{East}$, $90^\circ = \text{North}$).

## Layer Architecture & Categories

The DXF file organizes geometry across standard AIA CAD layers. The companion JSON categorizes each layer into functional BIM categories:

| Layer Name | CAD Color | BIM Category | Description |
| :--- | :--- | :--- | :--- |
| `A-WALL-EXTR` | Cyan | `walls` | Exterior perimeter load-bearing walls and wall jambs |
| `A-WALL-INTR` | Green | `walls` | Interior partition walls and room dividers |
| `A-DOOR` | Yellow | `doors` | Door leaves and 90° swing arcs |
| `A-GLAZ` | Blue | `glazing` | Window frames and glazing centerlines |
| `A-FURN` | Green | `furniture` | Movable furniture blocks (beds, sofas, tables, desks) |
| `A-FIXT` | Color 8 | `fixtures` | Sanitary plumbing fixtures and kitchen equipment |
| `A-STAIR` | Yellow | `circulation` | Staircases, treads, walk lines, and steps |
| `A-COLS` | Cyan | `structure` | Structural columns and load-bearing piers |
| `A-FLOR-FIN` | Color 8 | `finishes` | Floor finishes, wet-area tile patterns, and boundary hatching |
| `A-ANNO-TEXT` | Red | `annotations` | Room name labels and calculated floor areas |
| `A-ANNO-DIMS` | Magenta | `annotations` | Architectural dimension chains and extents |
| `0` | Default | `system` | Standard CAD base layer (kept strictly empty) |

## Architectural Element Block Categories

All reusable CAD blocks registered in the drawing and listed in `elements` belong to one of five architectural categories:

1. **`furniture`**: `BED-SINGLE`, `BED-DOUBLE`, `NIGHTSTAND`, `WARDROBE-STD`, `SOFA-2SEAT`, `SOFA-3SEAT`, `DINING-4SEAT`, `DINING-6SEAT`, `DESK-STUDY`, `CHAIR-DESK`, `TV-UNIT`
2. **`sanitary`**: `TOILET-STD`, `BASIN-STD`, `SHOWER-ENCL`, `BATHTUB-STD`
3. **`kitchen`**: `KITCHEN-COUNTER`, `KITCHEN-SINK`, `COOKING-HOB`, `REFRIGERATOR`
4. **`circulation`**: `STAIR-STRAIGHT`, `STAIR-LSHAPED`, `STAIR-DOGLEG`
5. **`structural`**: `COL-SQUARE-300`, `COL-RECT-200X400`

## Semantic Data Model

### 1. Floors & Levels
```json
"floors": [
  {
    "id": "LEVEL-01",
    "name": "Ground Floor",
    "elevation": null,
    "height": null,
    "envelope": {
      "width": 6000.0,
      "depth": 5000.0,
      "origin": [0.0, 0.0]
    }
  }
]
```
> [!IMPORTANT]
> **No Guessing Vertical Heights in 2D**: In 2D floor plans, elevation and storey heights are unannotated unless explicitly measured. They are stored as `null`. Downstream BIM skills MUST prompt the user for vertical parameters rather than fabricating standard heights.

### 2. Walls and Host-Wall Relationships
```json
"walls": [
  {
    "id": "W-EXT-01",
    "classification": "exterior",
    "start": [0.0, 0.0],
    "end": [6000.0, 0.0],
    "thickness": 200.0,
    "layer": "A-WALL-EXTR",
    "floorId": "LEVEL-01",
    "openingIds": ["D-01", "W-01"],
    "source": "explicit"
  }
]
```
- Each wall specifies its centerline `start` and `end`, thickness in mm, and layer assignment.
- `openingIds` lists all hosted doors and windows embedded within this wall segment.

### 3. Openings (Doors & Windows)
```json
"openings": [
  {
    "id": "D-01",
    "type": "door",
    "wallId": "W-EXT-01",
    "center": [1200.0, 0.0],
    "width": 900.0,
    "height": null,
    "sillHeight": null,
    "swing": "90_deg_single",
    "floorId": "LEVEL-01",
    "source": "explicit"
  }
]
```
- `wallId` anchors the opening directly to its host wall.
- `center` defines the 2D coordinate along the wall axis.
- `height` and `sillHeight` default to `null` in 2D, leaving vertical heights to downstream approval.

### 4. Elements & Finishes
```json
"elements": [
  {
    "id": "ELEM-BED-01",
    "blockId": "BED-DOUBLE",
    "category": "furniture",
    "position": [1800.0, 3600.0],
    "rotation": 0.0,
    "scale": 1.0,
    "floorId": "LEVEL-01",
    "roomId": "ROOM-BED-01",
    "layer": "A-FURN",
    "status": "approved"
  }
]
```
- Each element maps to a registered CAD block reference (`INSERT` entity in DXF).
- Associated with its enclosing room (`roomId`) and floor level (`floorId`).

## Relationship Between DXF and Companion JSON

1. **Dual Generation**: When `DrawingGenerator.build_drawing(...)` executes, it translates the approved floor-plan model into CAD vector commands, exports the DXF, inspects the drawing, and immediately compiles `<drawing-name>.handoff.json`.
2. **Entity Consistency**:
   - Total entity count in DXF matches `dxf.entityCount`.
   - Number of block references (`INSERT`) matches `elements` count.
   - Number of pattern hatches (`HATCH`) matches `finishes` count.
   - All layer names in DXF are registered in `dxf.layers`.
3. **Handle Stability**: CADCraft entity handle numbers are ephemeral session handles that change upon file reload. The companion JSON relies entirely on stable semantic identifiers (`id`, `wallId`, `roomId`, `blockId`).

---

## Downstream Consumption by `dxf-to-3d-bim`

The downstream 3D BIM skill consumes both files as follows:
1. **Load Companion JSON**: Read `<drawing-name>.handoff.json` to extract wall centerlines, thicknesses, opening host IDs, and room bounding polygons without error-prone vector tracing.
2. **Verify DXF Geometry**: Inspect `<drawing-name>.dxf` using CADCraft or CAD engine to verify graphical integrity and layer compliance.
3. **Vertical Parameter Gate**: Query the human user for vertical elevations (storey height, window sill height, door head height) as mandated by the BIM approval workflow.
4. **Extrude to 3D**: Generate native 3D geometry and IFC4 building models.

## Current Limitations & Roadmap

- **Single Storey Scope**: The current contract and drawing workflow produce single-storey drawings (`LEVEL-01`). Multi-storey floor plans will be split into individual floor drawings and linked via multi-storey metadata in Milestone 6.
- **Architectural Reports**: Comprehensive schedules (room areas, opening schedules, element counts) will be generated in Milestone 5.
